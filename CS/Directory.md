A truth table redrawn on a **Gray-code** grid so any two neighbours differ in exactly one variable — which turns the one move minimisation ever makes (the **adjacency law** $XY+X\overline{Y}=X$: two terms differing in one variable merge, dropping it) into a visual act: **loop the biggest rectangles of 1s.** Grouping rules (rectangles of $2^k$ cells, as large + as few as possible, overlap allowed, and the map is a **torus** — edges wrap, so the four corners are one group); reading a loop (the constant variables survive, the changing ones drop); the **majority function** minimised by eye to $AB+AC+BC$ — the same function [[Logic Gates]] built by DNF, giving the vault a three-card "one function, three methods" through-line; a 4-variable worked map (a group of 8 → a single literal; a wrap-around corner group → $\overline{B}\,\overline{D}$); **don't-cares** as free real estate; POS by grouping the 0s (where [[Boolean Algebra|SOP↔POS duality]] becomes visible). 3. **[[Half-Adder and Full-Adder]]** — arithmetic from gates, and the synthesis point of the whole gates → algebra → maps arc: a computer *does arithmetic by doing logic*. The **half adder** adds two bits (Sum $= A\oplus B$ = XOR, Carry $= A\cdot B$ = AND) but has no carry-in — good only for the rightmost column. The **full adder** adds three (Sum $= A\oplus B\oplus C_{in}$ = **parity**; $C_{out}=AB+AC_{in}+BC_{in}$ = **the majority function** — the exact circuit [[Logic Gates]] built by DNF and [[Karnaugh Maps]] minimised, now doing its real job as *the carry bit*), and the 9618 favourite is to build it **from two half adders + an OR**. Chain $n$ full adders → a **ripple-carry adder** ($7+1=8$, the carry sweeping left like $0999\to1000$), whose carry-propagation delay sets a speed limit that real chips beat with **carry-lookahead**. **Subtraction is free**: two's complement means invert $B$ and set carry-in $1$, so one XOR-controlled adder does both $A+B$ and $A-B$ (and its top carry is the overflow signal — [[Overflow and Underflow]]). Beyond: multiplication as shift-and-add, and the [[Arithmetic Logic Unit]] the whole thing feeds. Three hand-drawn circuit schematics. Reserves [[Arithmetic Logic Unit]]. **Advances 9618 §15.2** (only flip-flops remain). Builds on [[Logic Gates]] + [[Number Bases]] + [[Boolean Algebra]].
4. **[[Flip-Flops]]** — the sequential half of 9618 §15.2, closing the bay: combinational circuits ([[Half-Adder and Full-Adder|adders]]) *compute*, sequential circuits *remember*, and memory is bought with **feedback**. One inverter in a loop demands $Q=\overline{Q}$ — no stable state, so it oscillates (the liar's paradox in silicon, kin to [[Stories/Russell's Paradox in the Post]]; odd loops are **ring oscillators**, used as on-chip clocks); two inverters in a loop satisfy $Q=Q$ twice — **bistable**, the two-state core of the SRAM cell. The **SR flip-flop** adds handles to the loop (cross-coupled NORs — with $S=R=0$ each NOR *is* a NOT and the circuit *is* the inverter loop; hold / set / reset / the forbidden $S=R=1$ whose simultaneous release is a race decided by manufacturing noise), the **clock** makes every flip-flop in the machine march in step (the GHz number), and the **JK** fixes the forbidden state by chaperoning each input with the opposite output ($S_{int}=J\cdot\overline{Q}\cdot clk$, $R_{int}=K\cdot Q\cdot clk$ — at most one path ever open), turning $J=K=1$ into **toggle** → frequency halving → **binary counters** (place value ticking in base 2). Role as data storage: registers = rows of flip-flops, SRAM cache = the bistable loop with access handles, status flags = one flip-flop each. Beyond: the **D-type** ($Q:=D$ on the clock edge — the flip-flop real register files and pipelines are made of; exam-front on OCR), race-around → edge-triggering and master–slave, latch-vs-flip-flop jargon, the J-K naming folklore (Eldred Nelson's patent lettering, not Jack Kilby). Four hand-drawn schematics (paradox-vs-memory loops, SR, JK, toggle timing) + a **four-mood SR SMIL animation** (hold / set / reset, then the chip visibly panicking — X-eyes and all — on the forbidden $S=R=1$). **Closes 9618 §15.2 and the bay.** Cashes the bistable bridge from [[RAM and the Memory Hierarchy]] and the stateless-gates warning planted in [[Logic Gates]]. The `domain/computer-architecture` tag stays: the academic **domain** is one axis, the pedagogical **bay** another.)*

### Deep cards (9)

1. **[[Turing Machine]]** — the 1936 *theoretical* universal machine and the **root of the lineage**: an infinite **tape**, a read/write **head**, finitely many **states**, and a **transition-function** rule-book — the minimal model of *what it means to compute*. The **universal machine** (one machine simulates any other from a description on its tape) is the stored-program idea in embryo; the **halting problem** is the first provably *uncomputable* question (full diagonal proof, à la Cantor); the **Church–Turing thesis** says this class *is* computation. A hand-run **binary-increment** trace (the same `PC+1` the FDE card does in hardware), an anatomy SVG, and a 4K **busy-beaver** Manim clip (3 states, halts in 14 steps → ties straight to undecidability). *Enrichment — not on 0478/9618, but the best answer to "why is a computer general-purpose?"* Lineage: Turing → [[Von Neumann machine]] → the FDE CPU.
2. **[[Von Neumann machine]]** — the 1945 **stored-program** leap that made Turing's universal machine buildable. The defining idea: **program and data share one read/write memory**, and instructions are *just numbers* — so you reprogram by **loading different numbers, not rewiring** (the ENIAC-plugboard → EDVAC jump). What code-as-data unlocks (assemblers, compilers, bootstrapping, self-modifying code — and the buffer-overflow shadow); the five "organs" (brain-inspired, via McCulloch–Pitts neurons); the **von Neumann bottleneck** and the **Harvard** rival; and the honest **credit story** (Eckert & Mauchly written out — a [[Stigler's Law of Eponymy]] classic). A vN-vs-Harvard SVG and a 4K **stored-program** Manim clip (one machine reprogrammed ADD → MULTIPLY by one number). Supports 0478 §3.1 + 9618 §4.1 (the *why* behind the FDE card's *what*).
3. **[[CPU Architecture and the Fetch-Execute Cycle]]** — the von Neumann **stored-program** model and the loop at the heart of every computer. CU + ALU + **registers** (the five exam registers **PC/MAR/MDR/CIR/ACC** + status) + the three **buses** (address/data/control); the **fetch→decode→execute cycle traced register-by-register** (`PC→MAR`, read `→MDR→CIR`, `PC+1`, decode, execute); a worked 3-instruction trace computing `C=A+B`; **instruction sets & machine code** (opcode/operand); clock speed, cores, cache. Beyond-syllabus: the **von Neumann bottleneck**, **Harvard** architecture, **microcode**, and the **Turing → von Neumann → FDE** lineage. von-Neumann block-diagram SVG. **Closes IGCSE 0478 §3.1.1–2 + AS 9618 §4.1.** The model that the next card accelerates.
4. **[[Pipelining and Simultaneous Multithreading]]** — how one core does so much, and how the GPU makes the opposite bet. The **fetch–execute cycle** as the loop being sped up; **pipelining** (the laundromat insight — overlap stages so one instruction finishes per cycle; throughput vs latency, with a staircase timing diagram); hazards + **branch prediction**; **superscalar / out-of-order / speculative** execution as "the modern fast core"; **SMT / Hyper-Threading** (two instruction streams fill one core's bubbles — typically +15–30%, *not* 2×); and the **GPU** as the **SIMD** opposite bet (Flynn's taxonomy; latency vs throughput; why GPUs hate branch divergence → ties to [[Parallel and External Sorting]]'s bitonic-sort note). Two schematics (pipeline staircase; CPU-vs-GPU). Beyond-syllabus: **Spectre/Meltdown**, the **memory wall**, **Dennard scaling** + the multicore wall, branch predictors as tiny ML. **Advances 9618 §15.1 + §4.1 and 0478 §3.1.3.** Pairs with [[Stories/Dual-Core Craft]].
5. **[[RAM and the Memory Hierarchy]]** — the bay's memory card, on one thesis: memory has a single job (hold a bit) and two opposite physical answers. **DRAM** stores a bit as charge on a **capacitor** (a *1T1C* cell) — tiny and cheap, so it is *main memory* (GBs), but the charge **leaks**, forcing **refresh** (~every 64 ms) and making reads **destructive** (a sense amplifier dumps then restores the charge); the capacitor physics ($Q=CV$, the $RC$ leak) is reserved for [[Capacitors]] (E&M). **SRAM** stores a bit as the state of a **flip-flop** — cross-coupled inverters (~6T) locked into one of two stable states — so it *holds itself* (no refresh), reads fast and non-destructively, but is bulky/expensive, hence *cache + registers* (MBs); the bistable latch is the stateful element [[Logic Gates]] reserved for 9618 §15.2. The DRAM-vs-SRAM table then drives the **memory hierarchy** — registers → L1/L2/L3 (SRAM) → main memory (DRAM) → SSD/HDD — exploited by **locality of reference** (temporal + spatial) to give "the illusion of a memory as big as disk and almost as fast as a register", hiding the **memory wall**. The "random" in RAM = *arbitrary* access, not stochastic (contrast [[Turing Machine]]'s sequential tape; the $O(1)$ array-access assumption behind [[Big-O Notation]]). DRAM-cell + SRAM-cell + hierarchy schematics + a matplotlib refresh-sawtooth. **Closes the memory-hierarchy concept; advances 0478 §3.3.1 (primary storage) + 9618 §3.1 (memory + performance); deepens the §3.1.3 / §4.1 cache rows; previews §15.2 flip-flops.** Builds on [[Logic Gates]] + [[CPU Architecture and the Fetch-Execute Cycle]].
6. **[[Clock Domains and Metastability]]** — 💎 enrichment, grown from a student question about flip-flop frequency dividers: *why does a CPU have a base clock and a multiplier, with different parts running at different speeds?* Three moves. **One crystal, many clocks:** a chip runs a single ~100 MHz reference and derives every domain from it — multiply up with **PLLs**, divide down with counters — because power ($P\propto CV^2f$), clock **skew**, and per-core **DVFS** all forbid a single global clock. **The PLL multiplies by dividing:** a $\div N$ counter (the [[Flip-Flops|frequency divider]], run *backwards* inside a feedback loop) forces $f_{out}=N\times f_{ref}$ — so the CPU "multiplier" $N$ literally *is* a flip-flop divide ratio. **The seams are where it breaks:** crossing between unrelated clocks catches a flip-flop mid-change and knocks it **metastable** — the released $S=R=1$ race from [[Flip-Flops]], a ball balanced on the ridge that topples at random — tamed for one bit by a **two-flip-flop synchronizer** (MTBF $\propto e^{t/\tau}$, never zero) and for buses by **[[Gray Code]] + asynchronous FIFOs** (one bit changes at a time — the same adjacency that powers [[Karnaugh Maps]]). Beyond: **GALS**, jitter/skew, clockless logic, and why a missing synchronizer is the classic intermittent "fails once a week" hardware bug. Three hand-drawn schematics (clock tree, PLL-multiplier loop, metastability + synchronizer). Reserves [[Gray Code]]. *Not on any board — pure enrichment;* builds on [[Flip-Flops]] + [[CPU Architecture and the Fetch-Execute Cycle]].
7. **[[Secondary Storage]]** — the storage-media card, on one throughline: **nothing in nature is a bit** — every medium hands you a smeary analog quantity (magnetised grains, trapped electrons, laser reflections) and a **decision boundary** turns it back into a clean 0/1; the engineering is all in surviving the middle. **Magnetic (HDD):** platters/tracks/sectors, the head flying nanometres up (a jumbo jet at grass height), and the beautiful move — read **flux reversals, not levels**, because edges are self-referencing when amplitude drifts; seek + rotational latency as the price of moving parts. **Flash (SSD/SD/USB):** the **floating gate** — electrons quantum-tunnelled onto an insulated island, read by the shifted threshold voltage; block-erase (the "flash" name); NAND vs NOR; MLC/TLC/QLC pack 2/4/8/16 charge levels **numbered in [[Gray Code]] order** so one level of drift corrupts one bit, not four; oxide wear → wear levelling. **The ROM family** — mask ROM → PROM's blowable fuses → EPROM's quartz UV window (the floating gate's first mass-produced home, Intel 1971) → EEPROM → flash — each generation answering *"how do I change my mind?"* more gracefully (the 9618 PROM/EPROM/EEPROM LO verbatim). **Optical (CD/DVD/Blu-ray):** pits and lands on one spiral, read as **transitions-are-1s** *again*, and the **wavelength ladder** 780→650→405 nm — the disc never grew, the pen got finer. Plus **buffers** (the speed-mismatch shock absorber), **virtual memory** at IGCSE depth (pages between RAM and disk; why the 47-tab laptop churns), and **cloud storage** (someone else's disks — advantages/disadvantages honestly tabled). Two tool-named worked examples (7 200 rpm → ~13 ms vs the SSD's 60 µs — motors never beat wires; the photographer's justify-the-medium scenario). Misconceptions: deleting ≠ erasing; storage is a *lease*, not a purchase; never defrag an SSD. Beyond: PRML/Viterbi (the disk reads by *prediction* — [[Compression]]'s thesis running in hardware), HAMR, 3D NAND, tape libraries, DNA storage. HDD-anatomy + floating-gate + optical-ladder schematics + an SLC-vs-TLC charge-level figure. **Closes 0478 §3.3 (Data storage complete 🎉) + the secondary-storage/device-operation/ROM-family/buffer LOs of 9618 §3.1.** Cashes the [[RAM and the Memory Hierarchy]] reservations; builds on it + [[Gray Code]].
8. **[[Input and Output Devices]]** — the human-facing interface card, and the first of the split I/O pair, on one thesis: **the CPU only moves bits, so every peripheral is a transducer** — a translator between digital data and a physical form a human can produce (input) or perceive (output). **Input:** keyboard (scan codes) and optical mouse (frame-differencing), the **three touchscreen technologies** each with its physics + pro/con + fit-to-context (resistive = pressure shorts two layers, works gloved; capacitive = finger draws charge, multi-touch but needs a conductive touch; infra-red = a touch breaks a beam grid, any object + huge sizes), scanners (barcode timing / QR camera / 2D-3D), and camera/microphone as **ADC front-ends** bridging [[Image Encoding]] + [[Sound Encoding]]. **Output:** inkjet (liquid ink, nozzles) vs **laser** (toner + charged drum + laser + fuser — dry electrostatics, *not* ink, the classic lost-mark trap), 3D printer (additive, layer-by-layer), LCD-shutter vs **OLED-emit** screens (why "LED screen" usually means LED-*backlit* LCD), DLP/LCD projectors, speaker as the microphone reversed, and the **VR headset** as everything-at-once (two displays + lenses + head-tracking sensors + a latency-critical loop — the doorway to [[Sensors and Control Systems]]). Then **how I/O is actually done** — the CPU/device speed gulf and its three fixes: **buffers** (where data waits — cashing [[Secondary Storage]]), **polling vs interrupts** (how the CPU learns a device is ready — the save-state → ISR → restore-state sequence, cashing the [[CPU Architecture and the Fetch-Execute Cycle|FDE]] control-bus interrupt line; why interrupts *are* multitasking), and **DMA** (bulk transfer without the CPU carrying each byte). Two tool-named worked examples (describe-the-laser-printer in stages; choose-a-touchscreen-for-a-gloved-operator) + four misconceptions (LED≠OLED, laser≠ink, touchscreen-is-one-thing, the-CPU-doesn't-idle-on-slow-devices). Three schematics (the transducer frame, the touchscreen trio, the polling-vs-interrupt timeline), verified light+dark. **Closes 0478 §3.2.1–2 + the human-facing half of the 9618 §3.1 device-operations LO.** Builds on [[CPU Architecture and the Fetch-Execute Cycle]] + [[Secondary Storage]]; reserves [[Sensors and Control Systems]] + [[Embedded Systems]] + [[Interrupt Handling]].
9. **[[Sensors and Control Systems]]** — the world-facing twin of the split I/O pair, on one thesis: **a sensor is a transducer pointed at the world instead of a person** — and once both ends of the translation face the world (sensor in, **actuator** out), the human can leave the room. The **fourteen 0478 sensors** tabled with quantity measured + one-line physics + canonical context (acoustic → glass-break; accelerometer → airbag; moisture → irrigation…), the **humidity ≠ moisture** trap (air vs soil) pinned, and the sensing chain named explicitly: *physical quantity → analogue voltage → ADC → number* (resolution, calibration). The **actuator** as the hand — motor/valve/heater thrown via a **relay**, a milliwatt whisper commanding a kilowatt punch; 0478 files it under output devices, but it exists *to be noticed by a sensor*. Then the star: **monitoring vs control** — the open chain (river pH station: measure, log, alarm; a *person* closes the loop) versus the closed **feedback ring** (greenhouse: measure → compare with the **setpoint** → actuate → *the action returns in the next reading*); why the thermostat surfs a **two-threshold band** instead of machine-gunning one perfect target; **negative feedback** (response opposes deviation — shivering and sweating as the body's heater and fan) vs **positive** (the microphone screech); and the ring's pedigree — **Watt's flyball governor (1788)** and **Maxwell's *On Governors* (1868)**: the computer didn't invent the loop, it made the *decide* step programmable. Two tool-named worked examples (the greenhouse six-marker — "compares with stored value" + "continuously" as the classic dropped marks; night-irrigation sensor choice with the humidity distractor dismantled) + four misconceptions. Beyond: **hysteresis**/Schmitt trigger, **PID** (the 3-D printer's nozzle at 200 ± 1 °C, the drone's hover), **sensor fusion**/Kalman (how a VR headset knows which way is up), and feedback as deliberate re-coupling → [[Decouple and Recouple]]. Animated monitoring-vs-control SVG (the monitoring pulse *dies at the human*; the control pulse loops forever) + a matplotlib thermostat-cycle figure. **Closes 0478 §3.2.3 (§3.2 complete 🎉) + the monitoring-and-control LO of 9618 §3.1; advances IB A1.3.** Builds on [[Input and Output Devices]]; reserves [[Embedded Systems]].
10. **[[Embedded Systems]]** — the disappearing computer, on one thesis: **dedication, not power, is the boundary** — a computer system (processor, memory, I/O) built *into* a larger device for one **dedicated function**, classified by the **one-question test**: *can the user change what it does?* (Smartphone: crossed the line the day it could install apps — general-purpose. Server in a rack: still general-purpose — visibility is not the test. Washing machine: never.) Sharpened by the modern twist that **the hardware line itself is blurring** — cheap general-purpose ARM SoCs replacing MCUs in TVs, dashboards, washing machines — so the boundary has migrated from capability to **access** (signed firmware, locked bootloaders; the OpenWrt-flashed router and the jailbroken console as devices crossing the line in opposite directions): the test never asked about the chip, it asked about the user. The **microcontroller** anatomy — a complete von Neumann machine on one ¥2 chip: CPU core + **kilobytes** of SRAM (the deep economy of dedication: capacity for exactly one job, hence the cost and the watch-battery power draw) + flash holding the **firmware** (why PROM/EPROM/EEPROM exist — cashing [[Secondary Storage]]) + timers + ADC + GPIO. The **sealed ring**: the [[Sensors and Control Systems]] feedback loop with the processor hidden in the box — the washing-machine cycle walked as a 7-state ring (lock, fill, heat, wash, drain, spin, beep — every stage compare-sensor-with-setpoint, throw-actuator, incl. the spin interlock). The **five 0478 habitats** tabled with what each senses/decides/actuates + the virtue each stresses (appliances = cheapness; cars = **real-time** — the airbag's ~20–30 ms deadline; security = reliability; lighting = low power; vending = unattended service); **benefits and drawbacks as one symmetric trade** — every drawback is a benefit read backwards (fixed/cheap, un-updatable/reliable) — the 9618 balanced judgement. **Real-time** promoted to a concept: correctness includes the deadline, a late right answer is a wrong answer; RTOS vs the no-OS-at-all loop. Two tool-named worked examples (the classifier three-parter; the vending machine traced as input–process–output) + four misconceptions (smartphone-is-embedded, embedded-means-weak, firmware-is-hardware, upgrade-like-a-PC). Beyond: the **Apollo Guidance Computer** shedding tasks through the 1202 alarm (the RTOS creed working in 1969, firmware literally woven), **Mirai** and the IoT security bill ("the S in IoT stands for Security"), and the Super FX chip — the cartridge that out-computed the console. Three schematics (the changeability spectrum, MCU anatomy, the washing-machine ring with a circulating pulse), verified light+dark. **Closes 0478 §3.1.5 + completes 9618 §3.1 🎉.** Builds on [[CPU Architecture and the Fetch-Execute Cycle]] + [[Sensors and Control Systems]] + [[Input and Output Devices]]; reserves [[Interrupt Handling]] + [[Operating Systems]].
11. **[[Interrupt Handling]]** — the doorbell, the bookmark, and the discipline of being interruptible, on one thesis: **a machine that can only do one thing at a time appears to care about everything at once because it can be interrupted — invisibly.** The reading-a-novel metaphor carried end to end (finish the sentence, bookmark the page, answer the door, return to the exact word — and the bookmark *is* the program counter). The **cause families** tabled (I/O event, timer, hardware fault, exception, system call — not every interrupt comes from hardware: the doorbell rings from inside the house). The **six-step mechanism** as the exam's six-marker: signal raised on the control bus → the current instruction **completes** → checked at the **end of every F-E cycle** (the hidden fourth beat) → state pushed to the stack (**现场保护** — "protecting the scene") → **vector table** lookup → ISR runs and returns as if nothing happened — with the two quiet steps flagged as the classic dropped marks. **Priorities, nesting, masking, NMI** (nesting = a stack of protected scenes — why the save-area must be a stack). The **timer interrupt as multitasking itself**: no program volunteers to stop, so the scheduler *is* an ISR fired by a metronome — the kernel spends its life as an interrupt handler (9618 §16.1's low-level scheduling); the NES ran entire games inside the screen-refresh interrupt. The **price tag**: context-switch cost, ISRs-stay-short, interrupt latency as the embedded deadline currency, sleep-until-interrupt, and the honest floods-favour-polling trade. Two tool-named worked examples (the six-marker; classify-then-justify) + four misconceptions (never mid-instruction; ISRs don't run in parallel; software interrupts exist; polling isn't always worse). Beyond: Apollo's 1202 re-read as an interrupt storm with priority as policy, message-signaled interrupts (the tap became a packet), the pattern escaping into software (signals, event handlers, async/await), and the interrupt line as an async signal needing [[Clock Domains and Metastability]]'s synchronizers. Two schematics (the cycle's fourth beat + detour; the nesting timeline with stack snapshots), verified light+dark. **Closes 0478 §4.1.4 (§4's first green) + completes the 9618 §4.1 interrupt LO (row text PDF-corrected — the scaffold had omitted it) + opens 9618 §16.1 🔴→🟡.** Builds on [[CPU Architecture and the Fetch-Execute Cycle]] + [[Input and Output Devices]] + [[Embedded Systems]]; reserves [[Operating Systems]] + [[CISC vs RISC]].
12. **[[Assembly Language]]** — the CPU with the case off, on one thesis: **assembly is machine code with names on — one line, one instruction, nothing hidden.** The one-to-one rule as the boundary with high-level languages (a compiler *designs* many instructions per line; an assembler *transcribes* exactly one — what you write is what runs); the grouped Cambridge instruction set (movement, I/O, arithmetic, compare, jumps, the bitwise family on register contents); **addressing modes as hop-counting** (immediate 0 hops, direct 1, indirect 2, indexed 1 + IX, relative from the PC — say the hops, take the marks); trace-table discipline in two worked traces (the CMP/JPN loop round by round) + a 4K Manim live trace; and the **two-pass assembler** derived from its cause — the forward reference — with symbol-table and substitution passes both worked. Beyond: real x86/ARM side-by-side + godbolt, the hand-assembled classics (SMB, RollerCoaster Tycoon, the Apollo listings taller than Hamilton), reading-as-X-ray (performance, security, embedded). Three schematics (the tower, hop-counted modes, the two passes) + the Manim, verified light+dark. **Closes 0478 §3.1.4 — the 0478 map's last 🟡 — and 9618 §4.2 + §4.3 🟢🟢** (§4.3's mechanics were complete in [[Bitwise Operations]]; the register-form instructions close the wording honestly). ## Data Structures (3 cards — bay OPEN 🎉)

1. **[[Arrays]]** — the bay's floor, written after the two cards that stand on it. Problem before tool: thirty scores in thirty variables cannot be looped over, because **a loop counts and `s1` is not a number** — so an array is what you get when you make a *name computable*, trading names fixed at writing time for arithmetic evaluated at run time. The spine is that Cambridge's own three-clause definition (**fixed length · identical data type · consecutive index numbers**) is not three rules but one: every clause is forced by $\text{address}(i) = \text{base} + (i-l)\times\text{size}$ — identical type because the multiplication needs a constant `size`, consecutive indices because the arithmetic assumes even spacing, fixed length because a contiguous block cannot grow into memory it doesn't own. What the restrictions buy is **$O(1)$ access: the array never searches, it calculates**, which is the assumption half of algorithmics rests on. The 0-vs-1 argument is then *derived away* — the index is an **offset**, a distance from the start, so 0 is what the arithmetic says and 1 is the arithmetic plus a courtesy; upper/lower bound and the $u-l+1$ fence-post follow. Out-of-bounds as the one place the abstraction leaks (Python raises, C does not — the buffer overflow, and [[Operating Systems]]' memory protection as the outer wall). 2D as **the grid that is secretly a line**: row-major order, the exam's single-bracket form against Python's list-of-lists, and the claim measured rather than asserted — the same 36 million additions run **four to five times slower down the columns than along the rows**, [[RAM and the Memory Hierarchy]]'s locality with a stopwatch on it. Then **the name is not the box**: `b = a` aliases, arrays pass **BYREF** (a mark in its own right), and the famous `[[0]*3]*2` grid trap is the identical fact in disguise. Closes with **records** as the inverted complement — an array is indexed by something that varies, a record by something that doesn't — motivated by the fragility of parallel arrays and landing on the array-of-records that real Paper 2 scenarios declare. Two schematics plus a three-beat 4K Manim — the grid unrolling into a line, one cache line serving eight additions along a row, then the same line serving one addition down a column with seven values dragged in and discarded. **Closes 0478 §8.2 (§8's first greens) and 9618 §10.2, advancing §10.1 to 🟡 — the record-declaration dialect is the only concept-side gap left in Section 10 besides Files.**
